The two UTI types are enough to hold the HTML and the plain text together. |

## S2 Deep link

| Question | Method | Result | Decision |
|----------|--------|--------|----------|
| Does `mockHost` refuse a `shell.openExternal` made after an awaited `plugin.request`? | Throwaway components test in a `mktemp` directory outside the repo (a panel plus a `*.test.tsx` and a minimal manifest), run with `orca plugin test`. | Does real Orca keep the press valid across an await? | Read of the renderer bundle `PluginPanel-DUbeP79j.js` in `app.asar.unpacked` (read only). | A press grants a gesture only when the control has been on screen unchanged for 500 ms (`isSettled`, `< 500` fails). Where `consumePress` is consulted was not traced. | An `await plugin.request(…)` before the open (a cold worker takes seconds) can outlive the 1 s grant in real Orca while passing `mockHost`. | What are the limits of `shell.openExternal`? | Recon (`docs/research/2026-11-03-recon.md`) and the Orca main process in `app.asar` (`d6e`, `_6e`, `m6e`, `v6e`). | Panel and editor only. http, https and mailto only (`url must be an http:, https: or mailto: URL`). 3 calls per 10 s for each window and plugin (`m6e = { maxMessages: 3, perMs: 1e4 }`); every call counts, including ones that show the dialog, and the limit throws `rate_limited`. On a refusal or `opened: false`, the results offer a separate "Open Teams chat" button, so channel posts are never repeated. The consent dialog appears on every open until the user ticks "Always allow", not once per host. |

## S3 PR fan-out

P is the number of code projects and N the number of my active PRs. Nothing here touches the network; the numbers are the budget Task 5 pins.

| Question | Method | Result | Decision |
|----------|--------|--------|----------|
| What does a visible PRs tab cost? | Count the calls per interval from the polling budget. | Every 60 s: 2P lists (my active and to-review, one each per code project). Every 5 min: P completed lists. Every 10 min: N work-item reads. Every 2 min: N policy-evaluation reads. Every hour: 1 repositories call. That is `2.2P + 0.6N + 1/60` calls a minute. | Task 5 pins these counts for P = 2. |
| What does a background poll cost? | The same count with the tab hidden. | Every 5 min: P to-review lists, `0.2P` calls a minute. Nothing else runs. | Task 5 pins this for P = 2. |
| What is the first visible load? | Sum of one pass over the budget. | `3P + 1 + 2N` calls (P active, P to-review, P completed, 1 repositories, N work-item reads, N evaluation reads), plus one work-item read per completed PR in the 14-day window. | Task 5's test expects, for P = 2: 2 active, 2 completed and 2 to-review lists, 1 repositories call, one work-items call per in-window PR and one evaluations call per active PR of mine; a run 60 s later makes 2 active and 2 to-review lists only. |
| What is the steady rate for a typical user? | P = 2, N = 10. | Visible 10.4 calls a minute (about 0.17 a second); background 0.4 a minute. | The rate is low; concurrency stays capped at 4 requests in flight per org (Task 5). |
| What do the formulas leave out? | Read against Task 5's enrichment text. | Work items of my completed PRs in the window are cached for 1 hour, so C completed PRs add `C/60` calls a minute (C is the completed count). Not part of the `N` term. | Task 5 counts them through "one work-items call per in-window PR". |
| How much `X-RateLimit-*` headroom does a visible refresh leave? | Not run. | Not measured. | **pending live** (Task 12): read-only on the client org. |
