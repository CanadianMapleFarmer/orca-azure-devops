# Azure DevOps for Orca: build roadmap

**Spec:** [`docs/superpowers/specs/2026-11-03-azure-devops-plugin-design.md`](../specs/2026-11-03-azure-devops-plugin-design.md)

The spec covers several largely independent subsystems, so the build is split into plans, and each plan ships working, testable software on its own. Each plan starts with the spikes (spec §7) that its own design depends on. A plan's detailed version is written once the plan before it has landed, because those spikes can change interfaces downstream.

| # | Plan | Delivers | Depends on | Spikes it settles |
|---|------|----------|------------|-------------------|
| 1 | **Foundation** ([detailed](2026-11-03-plan-1-foundation.md)) | Installable plugin with a sidebar hub; connect any org with the Azure CLI (private profile per org) or a PAT; account pinning; boards project and team plus code-project settings; ADO HTTP client with rate-limit handling | — | `az` on the worker's PATH; az account picker; tenant discovery |
| 2 | **Boards** | Sidebar "My work" (grouped by board column, PR chips, Move to, details with comments and parent); full-tab board custom editor with drag-and-drop between vertical columns; collapsed swimlanes; epic filter; "Move to next column?" nudge (off until configured); "Start a workspace" as a visible terminal command; polling scheduler | 1 | WEF-only moves; untitled `newFiles` tab behaviour; `terminal:send` / `terminal.create` route |
| 3 | **PRs and sharing** | PRs tab with release sets (approve all, auto-complete all with saved options); share composer with the reference format and template; destinations: rich-text copy, Teams Workflows webhook, Teams chat deep link, add reviewers; reusable `share` module | 1 | Rich clipboard per OS; deep-link behaviour; org-level PR fan-out cost |
| 4 | **Pipelines** | Runs list (Mine / Running / Needs me / Failed); full-tab live run view (stages, steps, live log tail, search, errors-only, error summary, jump to line, open file, rerun, cancel); environment approvals with Share (reuses Plan 3's `share`) and Approve/Reject; watched-run notifications | 1, 3 | Timeline change detection; log tail cost within TSTU |
| 5 | **Reviews and wiki (basic)** | "To review" inbox: description, files, read-only per-file diffs, threads (reply, resolve, new comment), votes, "Check out in Orca" (visible command); wiki tree, read, search, edit in the plugin's tab, publish with ETag conflict handling | 1, 2 | Wiki tab persistence (or the folder-project fallback) |
| 6 | **Sign in with Microsoft and release prep** | MSAL Node (auth code + PKCE, loopback) with a client-ID setting, cache in `orca.secrets`; README admin guide for the app registration; optional proxy/CA settings; icon, screenshots, `orca plugin inspect` review; publishing only when the user asks | 1 | MSAL loopback with Orca's external-link consent |
| 7 | **Orca 1.4.248 enrichment** (when it ships) | Status-bar build/PR badge; keep-warm hook and always-on notifications; `agent.prompt.before` work-item context; one-click workspace, check-out and tab opening via `workspace:write`, `editor.open`, `agent.launch` | 1–6 | — |

**Testing environment (spec §5.9):** everything that writes runs against the user's personal sandbox org. The client org is used for read-only checks only.
